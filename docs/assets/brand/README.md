# Brand assets

Cover images, explainers and the product icon. Everything here is generated by
[`tools/make_brand_assets.py`](../../../tools/make_brand_assets.py); edit that script, not the PNGs.

The cover is 2:1 so it doubles as the GitHub social preview image. The dark variants are
shown by GitHub through `<picture>` + `prefers-color-scheme`; clients that ignore the
`<source>` fall back to the light file.

The cover carries no sample answer text. Its right side is a stack of three cards with the
`K` on top: it suggests a pile of answers without printing any one of them, so the banner
stays true whatever the library contains. An earlier draft showed a rendered answer (a
graphene title with sources); that reads as a screenshot and ages with the copy.

The explainer follows the same rule on purpose: a headline states what the plugin does and
what it saves you from, and the two cards use labelled text bars instead of a sample
question and answer. Only category names appear (`section`, `page`, `DOI`, `citation
chain`), so the image does not age with an example.

## Type and the icon

Display text is Noto Serif SC (SIL OFL); mono labels are Consolas. The script looks for
them under `%WINDIR%\Fonts` and falls back to another serif/mono if one is missing; set
`KB_BRAND_SERIF` / `KB_BRAND_MONO` to pin exact files. Fonts are rasterised into the PNGs
and are not distributed with the repository.

The icon is the wordmark's initial: a **serif `K`** from Noto Serif SC Bold on a blue
rounded tile. It echoes the `K` chip in the answer pages' rail, and it stays legible at
16 px where a pilcrow or a thin pictogram turns to mush.
`icon.svg` embeds the glyph outline as a path — Noto Serif SC is SIL OFL, which allows
embedding — so the SVG does not depend on the viewer's fonts. `icon-32.png` and
`favicon.ico` use tighter padding and a slightly larger K than `icon-512.png`.

## Regenerate

```bash
python tools/make_brand_assets.py          # write the files
python tools/make_brand_assets.py --check  # verify sizes and the 1 MB social-preview limit
```

The script needs Python 3.9+, Pillow, and fontTools (only for `icon.svg`). It looks for
Noto Serif SC under `%WINDIR%\Fonts`; set `KB_BRAND_SERIF` to another font file if it is
missing.

## Where it is wired in

- `README.md` / `README_CN.md`: cover block at the top, then the two-page story
  (promise → mechanism) before the result example. The usage page opens the user
  manual, and the template grid closes the "ask" section.
- `docs/index.html`: favicon links, the icon next to the header eyebrow, and the
  hover accent set to the brand blue (`#1F5FA8`).

## Manual step: GitHub social preview

The image shown when the repository is shared is set in the GitHub UI, not by a file:
**Settings → Social preview → Upload an image**, using `cover-en-light.png`. GitHub's
limit is 1 MB; all four covers are well under it.

## Follow-ups

- The HTML answer page's rail already uses a `K` tile, so the icon and the product agree;
  no engine change is needed for this asset.
- The npm README is published from `npm-package/README.md`. npm does not resolve
  repository-relative image paths, so that banner needs an absolute
  `raw.githubusercontent.com` URL; add it with the next release.
